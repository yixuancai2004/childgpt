How the policy works

priority = 0.5(1 − mastery)
+ 0.3(staleness) + 0.2(relevance)

Current mastery = stored strength × 2^(−days since reinforcement / stability days), measured at whole-hour resolution. Staleness combines turns since recall with time-based forgetting. Direct questions and autonomous review use the same recall rule. Every fifth question-selection turn explores a new concept. The draw u is a hash, so every decision can be replayed. Bands: low < 0.30 ≤ medium < 0.70 ≤ high.

if a memory has a pending conflict:
    clarify()
elif exploration turn (every 5th):
    ask_to_learn(quoted mention or new concept)
else:
    item = highest priority
    u = hash(profile, item, turn)
    low:    ask_to_learn()
    medium: 40% recall, 30% unsure,
            30% controlled error
    high:   90% recall, 5% unsure,
            5% controlled error

# Autonomous correct recall at high mastery:
# practising → ask about use
# connecting → ask about a related concept

# Operators use taught content only:
# omit_step, swap_steps,
# confuse_related, approximate
# Never invent a replacement fact.

Teaching starts at 0.35 with a 3-day half-life. Repetition adds 0.10; confirmation adds 0.15; correction adds 0.20 to current mastery (minimum 0.35 after a reminder, maximum 1). Each reinforcement extends the half-life ×1.5, capped at 90 days. Recall alone gives no learning credit. Stages require breadth and reinforced lessons, not elapsed time or chat count. These are illustrative design parameters, not validated estimates of child development.

PRESENTATION REQUIREMENT 04

Evidence, not promises.

Run the actual controller tests and reproducible synthetic behavioural experiments.

SYNTHETIC DATA ONLY No older adults were recruited. These results do not establish wellbeing benefits or clinical validity.

01 · Functional evaluation

96 scripted controller checks, executed in this browser. No live-provider tests.

Run the suite to inspect measured pass counts. No assumed 100% scores.

02 · Personal-baseline change detection

First 20 days calibrate the baseline. Monitoring begins on day 21; a scripted change starts on day 31.

ONE-SIDED CUSUM

Standardized change score

Lower response rate, longer delay, shorter replies, fewer self-started turns and corrections → higher score.

Cumulative deviation

Sₜ = max(0, Sₜ₋₁ + zₜ − k); signal when Sₜ > h.

▧ Baseline   ┆ Injected change   ● First signal

03 · Repeated-run robustness

200 stable + 200 sustained-change + 200 three-day-dip sequences, plus a threshold sweep. The default h was fixed in advance.

A single attractive trace is not an evaluation. Run repeated simulations to expose false alarms and misses.

What these results do — and do not — show

IMPLEMENTATION EVIDENCE

A credible teaching loop

Boundary tests, recall, corrections and profile isolation show whether the implemented controller behaves as specified.

SIMULATION EVIDENCE

A visible change signal

False alarms and detection delay quantify the detector on our declared synthetic generator, not on elderly users.

STILL A HYPOTHESIS

Meaningful human benefit

Engagement, loneliness, authenticity and safety need consented user research. They cannot be concluded from this demo.

Scope and limitations

This is a software prototype for GP8001 Group 6, not a care service. Use invented examples, not personal, medical or identifying information.

Memory is explicit. A connected model writes natural replies within the selected action; templates remain available when the model is unavailable. Controlled errors follow explicit recall rules; a scripted omission is also available for demonstrations.

Optional invitations work only while this page is open. The backend has a seven-day session lifetime. Consent, age-appropriate field research, clinical validation and production security require separate work.

No analytics, third-party fonts or external scripts are embedded in this app. Public hosting has its own server logs.
