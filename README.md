## 最快打开

- 本地模型体验：双击 `Start ChildGPT.command`，或执行 `npm start`。
- 离线：用浏览器打开 **`ChildGPT-demo.html`**（运行 `npm run build` 生成）。单文件，不依赖 CDN 或外部资源。

首页提供两组演示，每组都可以“查看实测”或“现场演示”：

1. **聊天**：问候 → “I can tell you how to cook” → 为想象中的咖啡馆起名。没有知识写入。
2. **学习**：未知的月铃礼 → 自然语言教学 → 演示按钮指定漏记 → 自然语言纠正 → 按当前掌握度回忆。漏记只是输出策略，完整记忆仍保留。

现场演示会实际调用已连接的模型，使用独立会话，结束后可导出 JSON 或回到自己的聊天。没有模型时不能运行现场演示，但可以回看随项目保存的真实测试记录；单文件也内嵌这两份记录。实测记录是虚构内容，不是实时生成。

切换 **Learner A / Learner B** 检查记忆隔离。**Algorithm trace** 展示当次真实运行的动作、知识边界、记忆来源、掌握度、回忆决策与出错算子。**Evaluation lab** 跑测试和模拟，可下载 JSON、CSV 和图表 SVG。

默认入口是一个聊天框，无需先选择 Teach / Ask / Correct。例如依次输入：

```text
我们这里说的 tavi，就是大家一起喝茶的开心时刻。
你还记得 tavi 吗？
不对，是大家一起喝咖啡的开心时刻。
对，就是这个意思。
```

未连接模型时，常见中英文句式由本地规则识别；不清楚的表达会请求澄清。连接模型后，每条聊天消息会携带当前对话目标、最近六条消息和最多八条相关记忆，由模型提出教学、提问、纠正、确认或不确定信息的候选动作，再由控制器校验。概念可以引用上一轮，新事实仍必须来自当前用户原话。不确定信息先暂存；含糊的“对”不会自动解决两个冲突版本。**Advanced · structured controls** 保留手动操作，供调试与演示使用。

这版界面是供课程演示的研究原型，尚未经过老年用户可用性验证。

## 方法与算法（第 3 项）

LLM 不决定"孩子知道什么"。控制器先决定动作和允许使用的事实，LLM（可选）只负责措辞和从用户原话中抽取片段。

| 组件 | 实现 |
|---|---|
| 记忆 | 每个用户独立的记忆：概念、内容、话题、来源回合、掌握度、修改历史、相关概念、提到过的词 |
| 知识边界 | 只从该用户的记忆作答；没教过就选 `ask_to_learn`，不用预训练知识 |
| 对话策略 | `priority = 0.5(1 − mastery) + 0.3·staleness + 0.2·topic relevance`；每 5 轮探索一次新概念 |
| 澄清 | 前后教法冲突的记忆先存为待定，策略优先追问"哪个对？"，而不是直接覆盖 |
| 好奇心 | 教学时用引号标出的词（如 “kopi”）进入好奇心队列，探索回合会主动问 |
| 关键词图 | 同一话题且共享关键词、或内容中提到对方的概念之间连边；进入联想阶段后，高掌握度主动复习可据此追问联系 |
| 受控回忆 | 普通提问和主动复习统一使用当前掌握度：低 → 请教或提醒；中 → 40% 正确 / 30% 不确定 / 30% 受控出错；高 → 90% 正确 / 5% / 5%，主动复习可按成长阶段追问 |
| 出错算子 | `omit_step` 漏一步、`swap_steps` 两步顺序互换、`confuse_related` 与相关概念混淆、`approximate` 只记得前半；只重排或删减已教内容，从不编造，安全敏感内容不出错，存储的记忆不变 |
| 可复现 | 抽样值 `u = hash(用户, 记忆, 回合)`，每次决定都能从 trace 重放；没有隐藏随机状态 |
| 掌握度更新 | 新教 0.35；重复 +0.10、确认 +0.15、纠正 +0.20 加在时间衰减后的掌握度上，巩固后最低 0.35、最高 1；单纯回忆不加分 |
| 元数据与检测 | 5 个与内容无关的指标：回复率、回复延迟、回复长度、主动发起次数、纠正次数。用前 20 天建立个人基线，对加权 z 分数做单侧 CUSUM：`S_t = max(0, S_{t−1} + z_t − k)`，`S_t > h` 时报警 |

详见 [docs/IMPLEMENTATION.md](docs/IMPLEMENTATION.md)。

**如何回应提案的问题**：老人不需要主动"求助"，只是在教 AI 孩子；系统从教学互动的节奏变化中，相对于每个人自己的基线发现变化。代价是：阈值越低，发现越快，但误报越多，短暂的情绪低落或忙碌也会触发报警。所以这个信号只适合温和地提醒家人或社工"去问候一下"，不能当作诊断。

## 本地运行（前后端）

需要 Node.js 22+；**没有第三方生产依赖**。

```bash
npm start
```

## 接入模型 API

复制 `.env.example` 为 `.env` 后自行填写。`.env` 已被 `.gitignore` 排除，不会提交：

```dotenv
LLM_BASE_URL=
LLM_API_KEY=
LLM_MODEL=
APP_ACCESS_TOKEN=
ALLOWED_ORIGINS=
```

- `LLM_BASE_URL` 填兼容 Chat Completions 的前缀（通常含 `/v1`），模型需要支持 JSON 输出。三项 LLM 字段要么都填，要么都空。
- `APP_ACCESS_TOKEN` 是另外生成的应用口令，**不是模型密钥**；接入真实模型时至少 24 个字符。
- 模型只做两件事：结合当前对话识别意图并从用户原话中抽取**原文片段**，以及根据控制器指定的动作生成完整自然回复。概念只能来自当前消息、当前目标或该用户的相关记忆；新增内容必须是当前消息的子串。事实内容始终由控制器管理；出错、超时或不合法输出时，会明确退回本地语言规则和模板。
- 2026-10-18 已用 Groq 的 `qwen/qwen3.8-27b` 完成真实 API 检查：英文省略概念名的回答抽取，以及中文“教学 → 显式纠正 → 代词追问”的 HTTP 后端流程；随后升级输出层，并实测了中文问候、教学、指代追问、受控遗漏和未知词请教的自然回复。测试中发现并修正了两类意图误判及输出格式不稳定问题；这些检查不代表任意对话都会正确。仅发送虚构示例，测试会话已删除。这是联通与单例流程验证，不能代表总体语言质量。`tests/llm.test.mjs` 仍使用模拟提供商，自动测试不消耗 API 额度。

仓库不预设服务商或模型名。没有填写三项 `LLM_*` 配置时，不会调用任何 LLM。开放式语言理解需要配置模型并连接后端（本机页面自动连接）；本地规则只覆盖常见表达。连接模型后，回复按控制器指定动作自由组织语言；未连接或校验失败时使用模板。复杂故事理解、部分食谱修改仍需进一步实现。

免费起点：使用 **Groq Free plan** 上的 `qwen/qwen3.8-27b`。在 [Groq 控制台](https://console.groq.com/keys) 注册并创建自己的 API Key，保持 Free plan；填入本地 `.env`，不要把密钥发送到聊天或填进前端：

```dotenv
LLM_BASE_URL=https://api.groq.com/openai/v1
LLM_MODEL=qwen/qwen3.8-27b
LLM_API_KEY=在本地填写自己的API密钥
APP_ACCESS_TOKEN=独立生成的至少24字符应用口令
```

截至 2026-10-18，[官方免费额度表](https://console.groq.com/docs/rate-limits)列出该模型每分钟 30 次请求、每天 1,000 次请求，每分钟 8,000 tokens、每天 200,000 tokens；任何一个额度都可能先触发限制，以账户控制台为准。一轮对话最多两次请求，因此每日可用对话数还会受 token 用量影响。超限时本项目回退到本地规则，不会切换到收费模型；使用付费账户本身仍可能产生费用。[Groq 接口](https://console.groq.com/docs/api-reference)支持 JSON 输出；该 Qwen 模型的回复使用严格 JSON schema 固定动作和字段，正文仍由模型生成，适配器关闭 reasoning；中文理解质量仍需更广泛的真实调用评估。

付费替代项：OpenAI 的 [`gpt-5.4-mini`](https://developers.openai.com/api/docs/models/gpt-5.4-mini)，对应 `LLM_BASE_URL=https://api.openai.com/v1`。切换服务时，也要换成对应服务的密钥。

然后运行 `npm run check:llm`。这是**显式触发的真实 API 检查**，会发送虚构的 tavi 教学示例，最多执行两次模型请求并产生相应 API 用量；未配置时不会发请求。它验证上下文抽取和按动作生成回复，不代表已经验证开放式语言质量。通过后运行 `npm start`，打开本机页面即可自动连接；顶部显示配置的服务和模型，每条回复下方标明实际生成来源。远程页面才需要在 **Connect & privacy** 中填写后端地址和 `.env` 内的 `APP_ACCESS_TOKEN`。不要把模型密钥填进页面。

Mac 可双击 `Start ChildGPT.command`；脚本优先使用已安装的 Node，也可使用本机 Codex 自带的 Node 运行时。当前配置检查和 API 请求参数有模拟测试，但真实调用需要使用者自己的有效 API 凭证。接通后，意图识别和完整回复生成均使用模型；掌握度、询问策略和受控遗忘仍由控制器决定。

GitHub Pages 只托管静态页面，不运行 Node 后端。远程后端需要 HTTPS，并设置 `ALLOWED_ORIGINS=https://yixuancai2004.github.io`。

## 成长与遗忘（v1.2）

普通聊天里的提问、Recall、主动复习和邀请统一走同一套回忆策略。每条记忆保存上次巩固时的强度 `mastery`、巩固时间 `lastReinforcedAt`、保持时间 `stabilityDays` 和有效学习次数 `learningCount`。当前掌握度按整小时计算：

```text
currentMastery = mastery × 2^(−elapsedDays / stabilityDays)
```

初次教学强度为 0.35，半衰期为 3 天；3 天不复习后是 0.175。再次明确教学、确认或纠正，会把增量加在当前掌握度上（最低恢复到 0.35，最高 1），把半衰期乘以 1.5，最长 90 天。这里的半衰期是控制器参数，既不是内容删除期限，也不是模型参数训练。只提问、闲聊、模型自己回答或跳过邀请，不会强化记忆。低掌握度时，生成回复的模型拿不到原文，只收到“以前教过，但现在想不起，请求提醒”的动作要求。

成长按实际学习量推进，各项条件需要同时达到：

| 阶段 | 已学概念 | 至少巩固过一次的概念 | 有效教学 / 巩固总次数 | 表现 |
|---|---:|---:|---:|---|
| 初识 | 0 | 0 | 0 | 简短理解一个概念，需要时请教 |
| 练习 | 3 | 2 | 6 | 主动复习中的高掌握度正确回忆，可追问用法或例子 |
| 联想 | 6 | 4 | 18 | 可追问两个已学相关概念的联系，不自行编造关系 |

阶段不会因为几天没聊天倒退；具体知识仍会生疏。重复刷一个概念不能满足概念广度条件，普通聊天条数不计入学习。未确认或冲突信息没有学习加分。阶段、进展、当前掌握度和保持时间可在 Learning studio / Algorithm trace 查看。各 profile 独立保存，删除 profile 才重置成长。

这些是可调整的原型规则，不代表真实儿童年龄或经过验证的学习模型。v1.0/v1.1 记忆自动补字段并保留原文、强度、历史和来源；旧数据无法恢复未记录的每次巩固，因此从最近纠正或初次教学时间保守估计，初始半衰期设为 3 天。跨天与阶段测试见 `tests/learning.test.mjs`；后端的时间测试使用服务端注入时钟，不接受客户端修改时间。当前后端仍有 7 天会话到期限制，长期身份与永久记忆不在本次改动中。

## 日常相处与角色语气（v1.2.1）

Milo 可以打招呼、听你讲今天的小事、接着聊故事、玩明确是假装的小游戏，也可以只回应一句。日常聊天不必转成教学任务；好奇、玩心和对细节的反应属于对话风格，不会自动增加掌握度。教学与纠正不再强制每次复述、致谢或问“我理解对吗”。直接被问到身份时，会如实说明自己是 AI；不会编造现实中的家庭、吃饭或离线经历。

生成普通聊天时，只提供当前消息与本 profile 最近三个社交来回（最多六条，每条最多 600 字），支持接住上一句；教学回忆原文不混入这段上下文。受控遗忘和想不起的动作仍不带聊天上下文或当前用户原文。故事与假装游戏不会直接写为已学事实，记忆写入仍经过原有校验。内部 `help` 动作兼容旧 trace，现在表示“不写知识的普通对话”，不代表必须给操作说明。

未连模型或 API 失败时，兜底回复也会跟随中英文，对问候、晚安、安静陪伴、游戏邀请等做简短回应；不再返回含 tavi 示例的整段英文使用说明。本地规则无法替代完整语言理解。页面显示 **CONNECTED API** 才是模型对话；**KEY-FREE DEMO** 是本地演示，失败时会提示并在 Algorithm trace 显示原因。聊天中的动作标签默认隐藏，打开 Advanced 调试面板可查看。

## 自然表达与记忆存储

控制器先决定 `ask_to_learn`、`recall`、`controlled_recall`、`clarify` 等动作；语言模型接收该动作、允许使用的记忆、未确认候选和当前消息，生成完整回复。通常跟随用户语言，简短表达并按需要追问。模型输出只能改写当前助手消息，不能直接写记忆、改变掌握度或选择遗忘动作。

受控遗忘时，输出请求不包含原始记忆、聊天历史、当前用户原文或被遗漏的片段，只包含控制器处理后的回忆。对于这种动作，保留该片段及顺序，模型自由组织周围的表达；校验会拒绝补回原文中的遗漏片段。其他回复允许忠实改写。**自由文本的事实一致性主要依赖有限上下文和提示词约束；格式及原文校验不是语义正确性的证明，仍可能出现幻觉。**

当前没有数据库或向量索引。后端每个会话保存为 `data/sessions/<会话令牌的SHA-256>.json`（可用 `DATA_DIR` 改目录），每轮完成后通过临时文件和重命名保存整个状态。文件包含 Learner A/B 各自的记忆、最多 120 条聊天记录、对话目标和最多 1,000 条交互元数据。每条记忆保存概念、内容、话题、掌握度、保持时间、上次巩固时间、学习次数、教学来源、关联概念、待确认候选与最近 30 次纠正；每个 profile 最多 200 条记忆。JSON 是本地明文文件，文件权限为 `0600`，不进入 Git 或静态构建；并非加密数据库。

会话创建后 7 天到期，并不会因为继续聊天而自动续期。浏览器使用 `sessionStorage` 记住后端会话凭证；同一标签页刷新可恢复，重新建立连接会创建新会话。浏览器的纯本地演示默认只保存在内存，打开 Remember 选项才写入 `localStorage`。因此长期养同一个孩子仍需要持久身份、会话恢复及独立于会话过期的长期记忆设计。

## 文件结构

```text
src/core.js             浏览器和后端共用的确定性控制器、CUSUM、合成实验
src/llm.mjs             服务端模型适配：原文片段抽取、完整回复生成
src/realization.mjs     输出动作与知识范围、遗忘上下文过滤、结果校验
server.mjs              Node HTTP 后端：会话隔离、文件持久化、CORS、限流
web/                    前端源文件
scripts/                构建、评估、发布脚本
tests/                  控制器、API、HTTP 和可选浏览器测试
results/                实际运行生成的 JSON、CSV、摘要与界面截图
docs/IMPLEMENTATION.md  与提案逐项对应的实现说明
docs/HANDOFF.md         给负责展示的组员：演示与取结果步骤
.github/workflows/      测试与 Pages 自动部署
```

## 重要边界

- 记忆从空白开始，示例都是虚构资料。浏览器本地保存默认关闭。
- Learner A / B 只是演示分区，不是登录系统；后端用随机 bearer token 隔离访问者，但未经生产级安全审计。
- 安全敏感内容用关键词拦截，不出错；关键词拦截并不是通用的内容安全系统。
- 掌握度增量、出错概率、检测权重和数据生成分布都是本原型自行设定的示例参数，不是经过验证的数值。

## 前端实测与连接修复（v1.2.2）

此前后端已经接入 Groq，但前端默认停在离线模式，导致正常聊天仍落到短模板。现在本机服务用运行时随机凭证自动建立会话，仅对绑定回环地址、合法 localhost Host、同源页面及同源 POST 生效；不会把模型密钥或应用口令注入页面。`LOCAL_AUTO_CONNECT=false` 可关闭此功能。静态构建不包含运行时凭证。

回复来源与模型配置独立记录：历史未记录来源的回复不会被追认为模型回复；429、超时和非法输出会显示降级原因。“重试模型回复”只重新生成当前话语，不重新教学、不增加掌握度。演示遇到限流会显示倒计时，并最多重试两次；失败的演示不会显示完成。

2026-10-18 在浏览器中点击两组现场演示，聊天 **3/3**、学习 **5/5** 条回复均由 Groq `qwen/qwen3.8-27b` 生成，随后通过页面导出保存：

- `results/demos/conversation.json`：包括原先失败的做饭邀请，现在回复 “Oh, a whole recipe? I'm listening.”
- `results/demos/learning.json`：存储内容由蓝绳纠正为红绳，完整的铜铃步骤保持，2 次学习、1 次纠正；演示结束时掌握度 55%。

这些是八轮实际前端调用的结果，不代表对所有自然语言的可靠性保证。原会话独立保留，同一标签页刷新恢复原会话。入口 `?demo=conversation#studio` / `?demo=learning#studio` 可直接查看相应实测回放。
